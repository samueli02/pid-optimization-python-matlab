소프트웨어랩 Term Project 발표 대본
주제: 머신러닝과 수치 미적분을 이용한 Python PID 탐색 및 MATLAB 독립 검증
상태: 녹화 전 초안. 발표 영상은 아직 제작하지 않았다.
목표 길이: 약 5분. 아래 시간은 편집 계획이며 실제 녹화 길이가 아니다.
대괄호의 화면 지시는 읽지 않는다. 학번·이름은 작성 필요다.

[슬라이드 1 / 00:00~00:15 / 주제]
이번 프로젝트는 사용자가 전달함수를 정하면 Python이 PID 값을 찾고, 그 값을 MATLAB에 적용해 확인하는 프로그램입니다. PID 응답에는 수치 미적분을 사용하고, 다음 후보를 고를 때 머신러닝을 사용합니다.

[슬라이드 2 / 00:15~00:40 / 입력 모델]
기본 예제는 다섯 개의 극점과 시간지연이 있는 시스템입니다. 분자와 분모의 계수를 직접 바꿀 수 있고 목표값과 관측 시간도 설정합니다. 이 모델은 직접 정의한 학습용 모델입니다. 실제 장비에서 측정해 식별한 모델이라고 주장하지 않습니다.

[슬라이드 3 / 00:40~01:10 / 미분·적분]
3강의 적분·미분을 실제 제어 계산에 적용했습니다. 적분항은 현재 오차와 이전 오차 사이의 사다리꼴 면적을 누적합니다. 미분항은 두 오차의 차분에 필터를 적용합니다. 세 항을 더해 제어입력을 만들고 응답을 계산합니다. 성능 기준인 ITAE는 시간에 오차의 절댓값을 곱해 적분합니다. ISE는 오차의 제곱을 적분합니다.

[슬라이드 4 / 01:10~01:40 / 머신러닝 데이터]
7강 머신러닝의 학습과 예측 개념을 응용했습니다. GP는 이 프로젝트에서 따로 선택한 확장 방법입니다. 여러 PID 조합을 실제로 시뮬레이션해 비용과 안정성 데이터를 만듭니다. 안정하고 유효한 데이터로 비용의 로그를 학습하고, 다른 GP로 안정성 지표를 학습합니다. 코드에서 GaussianProcessRegressor의 fit과 predict를 실제로 호출합니다.

[슬라이드 5 / 01:40~02:05 / 후보 추천]
학습 모델은 비용의 예측값과 불확실성을 줍니다. 이를 기대개선이라는 기준으로 계산하고 안정성 추정도 반영해 다음 후보를 추천합니다. 추천값은 반드시 실제 시뮬레이션으로 다시 확인합니다. GP 예측이 좋다는 이유만으로 최종 제어기를 채택하지 않습니다. 기존 Nelder-Mead는 이런 예측 모델을 학습하지 않는 비교용 수치 탐색입니다.

[슬라이드 6 / 02:05~02:25 / 데이터 분리]
기본 실행의 전체 평가 180개 중 156개는 학습과 탐색, 24개는 별도 검증에 사용했습니다. 마지막 모델을 동결한 뒤 최종 PID 주변에서 새 검증 후보를 만듭니다. 검증 표본은 학습이나 다음 후보 추천, 최종 PID 선택에 다시 넣지 않습니다.

[슬라이드 7 / 02:25~03:05 / 실제 실행 데모 40초]
[10초: 전달함수 입력과 PID 슬라이더를 실제 조작한다.]
전달함수와 PID를 바꾸면 출력과 성능 지표를 확인할 수 있습니다.
[10초: ITAE, seed 42, 예산 180을 표시하고 ML 최적화를 시작한다.]
이제 같은 모델에서 데이터를 만들고 학습한 뒤 PID를 추천하도록 실행하겠습니다.
[10초: 실제 진행 단계와 학습 표본 수를 보여준다. 시간이 길면 중간을 편집하되 시작과 완료를 모두 보여준다.]
[10초: 응답 비교, 학습 보고서, 파일 저장을 보여준다.]
결과가 나오면 응답뿐 아니라 학습 데이터와 예측 검증 자료도 확인하고 저장할 수 있습니다.

[슬라이드 8 / 03:05~03:35 / 실제 결과]
[results/ml_benchmark/ml_response_and_search.png와 같은 실행의 표를 사용한다.]
기본 실행에서 ML 선택의 ITAE는 약 58에서 5.45로 줄어 90.59퍼센트 감소했습니다. 오버슈트는 약 11퍼센트로 증가했습니다. 같은 총 예산의 Nelder-Mead는 ITAE가 약 5.16으로 이번에는 더 낮았습니다. 따라서 머신러닝을 썼으니 항상 더 좋다고 말할 수는 없습니다.

[슬라이드 9 / 03:35~04:00 / 예측 검증]
[results/ml_benchmark/ml_validation.png를 보여준다.]
국소 검증 표본 24개에서 로그 비용의 평균 절대오차는 약 0.036, RMSE는 약 0.043, R제곱은 약 0.829였습니다. 이는 최종 PID 주변에서의 예측 결과입니다. 모든 PID 범위나 다른 전달함수에서도 같은 정확도가 나온다는 뜻은 아닙니다.

[슬라이드 10 / 04:00~04:20 / MATLAB]
[results/ml_benchmark/matlab의 실제 비교 그래프와 JSON을 보여준다.]
최종 설정을 MATLAB에 넘겨 응답을 독립적으로 계산했습니다. 출력의 최대 차이는 약 3.33 곱하기 10의 마이너스 15승으로 허용값 10의 마이너스 7승을 통과했습니다. Python의 출력 데이터를 MATLAB의 계산 결과로 재사용한 것은 아닙니다.

[슬라이드 11 / 04:20~04:45 / 한계]
이번 데이터는 선형 모델에서 만든 합성 데이터입니다. 실제 잡음과 포화, 외란은 검증하지 않았습니다. 커널 설정도 고정했고 검증 범위도 최종 PID 근처입니다. 전역 최적이나 실물 장비 성능을 보장할 수 없습니다. 모델이 바뀌면 데이터를 새로 생성해 학습해야 합니다.

[슬라이드 12 / 04:45~05:00 / 결론]
미적분은 PID 응답과 비용 계산에, 머신러닝은 다음 후보 선택에 사용했습니다. 마지막 결과는 MATLAB에서 독립적으로 확인했습니다. AI가 작성한 초안은 수식과 실제 실행 결과로 점검했고 코드와 근거 데이터를 함께 공개합니다.

녹화 전 점검
1. 실제 실행 데모를 최소 30초 이상 포함한다. 위 계획은 40초다.
2. 슬라이드와 대본의 수치는 results/ml_benchmark의 같은 실행을 사용한다.
3. 이전 results/benchmark의 91.10%를 ML 결과라고 말하지 않는다.
4. 화면 지시문을 읽지 않고, 실제 녹화가 4~6분인지 확인한다.
5. 최종 영상에서 달리 말한 부분은 이 대본에도 반영한다.
6. GP 출처: https://scikit-learn.org/stable/modules/gaussian_process.html
